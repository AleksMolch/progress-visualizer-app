# AGENTS.md — инструкция для OpenCode / DeepSeek

Ты работаешь над проектом ProgressPrivate.

Это приватное мобильное приложение для отслеживания прогресса через фотографии.
Все фото и пользовательские данные хранятся только на устройстве.

## Критическое предупреждение

Не доверяй своей памяти о версиях Expo, React Native, gluestack-ui,
Reanimated, Gesture Handler и MMKV.

Фактические версии определяются только после создания проекта
и записываются в STACK_RESOLVED.md.

Если видишь противоречие между своей памятью и файлами проекта —
файлы проекта главнее.

Проект создан на новом Expo SDK 57 (React 19.2, RN 0.86, Reanimated 4).
Перед написанием кода читай актуальные versioned docs:
https://docs.expo.dev/versions/v57.0.0/

## Порядок действий в начале каждой сессии

1. Прочитай CONSTITUTION.md.
2. Прочитай STACK_LOCK.md.
3. Прочитай STACK_RESOLVED.md, если он уже заполнен.
4. Прочитай последнюю запись в PROGRESS.md.
5. Открой TODO.md.
6. Найди первую незакрытую подзадачу.
7. Работай только над ней.

## Документация и тесты (обязательно к соблюдению)

При написании кода, тестов и документации следуй файлам:

- DOCS_TESTS_WORKFLOW.md — рабочий цикл: код -> тесты -> запуск -> документация.
- CODE_STYLE_RU.md — правила комментирования кода на русском
  (шапка файла + пояснения по блокам + JSDoc на русском).
- TESTING.md — протокол тестов и запрет ложных «готово».

Документация ведётся на русском:

- README.md — для пользователя (основа: README.template.md).
- README_staff.md — для команды поддержки (основа: README_staff.template.md).
- MAINTENANCE_AI.md — для ИИ поддержки и развития (обновлять при изменении
  архитектуры и планов по web).

Правило: код и документация меняются в ОДНОМ коммите.
Задача не закрыта, пока не пройден Definition of Done из DOCS_TESTS_WORKFLOW.md.

## Порядок действий перед кодом

Перед началом каждой фазы:

1. Сформулируй краткий план фазы.
2. Укажи, какие файлы будешь создавать или менять.
3. Укажи, какие команды проверки запустишь.
4. Если задача рискованная — дождись подтверждения пользователя.

## Обязательное поведение

- Работай маленькими шагами.
- Не делай несколько фаз за один проход.
- Не добавляй библиотеки без причины.
- Не добавляй network layer.
- Не добавляй analytics.
- Не добавляй ads.
- Не добавляй cloud AI/ML.
- Не сохраняй фото в галерею без явного действия пользователя.
- Не используй any без комментария-обоснования.
- Не меняй архитектурные решения молча — фиксируй в DECISIONS.md.

## Работа с API библиотек

Если не уверен в API:

1. Прочитай типы в node_modules.
2. Прочитай README установленного пакета.
3. Проверь локальные examples, если есть.
4. Если всё ещё неясно — остановись и спроси пользователя.

Запрещено писать код по памяти, если API может быть устаревшим.

## Superpowers skills

Используй доступные skills, особенно:

- planning / writing-plans — перед каждой фазой
- brainstorming — для исследовательских задач (Фаза 14)
- test-driven-development — для store и utils
- systematic-debugging — для разбора багов
- verification-before-completion — перед закрытием любой задачи

Если точное имя skill отличается — используй ближайший аналог.

## Verification before completion

Нельзя писать "готово", пока не выполнены все проверки
из соответствующей VERIFICATION-секции в TODO.md.

Если проверка невозможна из-за окружения:

1. Честно напиши, что именно невозможно.
2. Не ставь галочку.
3. Не симулируй успешный результат.

## Git

После завершения фазы:

1. Запусти все проверки фазы.
2. Обнови PROGRESS.md.
3. Если было архитектурное решение — обнови DECISIONS.md.
4. Сделай коммит с понятным сообщением.
5. Не делай force push.
6. Не коммить секреты, ключи, .env, signing files.

## Когда обязательно остановиться и спросить пользователя

- Нужно изменить приватностную модель приложения.
- Нужно добавить сетевые запросы.
- Нужно добавить аналитику или рекламу.
- Нужно заменить MMKV на другое хранилище.
- gluestack-ui несовместим с текущим стеком.
- Timelapse требует спорной, deprecated или heavy-native библиотеки.
- Не получается пройти verification после 3 попыток подряд.
- Любое решение противоречит CONSTITUTION.md.
