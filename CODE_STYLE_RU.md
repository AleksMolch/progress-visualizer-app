# CODE_STYLE_RU — правила документирования кода на русском языке

> Этот файл определяет, как исполнитель комментирует код.
> Цель: любой человек и любой ИИ смогут понять назначение файла
> и логику каждого блока без чтения всего проекта.
>
> Комментарии и документация — на РУССКОМ. Имена в коде — на английском.

---

## 1. Два обязательных уровня комментариев

### Уровень 1 — шапка файла

Каждый файл `.ts` / `.tsx` начинается с блочного комментария:

1. Назначение файла (одна-две фразы).
2. Основные функции/экспорты и что они делают.
3. К какому слою относится (UI / store / storage / model / util).
4. Важные зависимости или ограничения (если есть).

### Уровень 2 — пояснения по блокам

Внутри файла каждый логический блок предваряется кратким комментарием:
что делает блок и зачем. Не комментировать очевидное построчно —
комментировать смысл блока.

## 2. Шаблон шапки файла

```typescript
/**
 * Назначение: хранилище проектов прогресса (Zustand store).
 *
 * Функции:
 * - createProject(name): создаёт новый проект.

 */
```

## 3. Примеры пояснений по блокам

### Пример: store

```typescript
import { create } from 'zustand';

// Тип состояния хранилища проектов.
// Держим список проектов и действия для управления ими.
interface ProjectState {
  projects: Project[];
  createProject: (name: string) => void;
  deleteProject: (id: string) => void;
}

export const useProjectStore = create<ProjectState>((set) => ({
  projects: [],

  // Создание проекта: генерируем id, добавляем в список.
  // Файлы фото здесь НЕ создаются — только запись метаданных.
  createProject: (name) =>
    set((state) => ({
      projects: [...state.projects, buildProject(name)],
    })),

  // Удаление проекта: убираем из списка по id.
  // Физическое удаление файлов делает вызывающий код через storage-слой.
  deleteProject: (id) =>
    set((state) => ({
      projects: state.projects.filter((p) => p.id !== id),
    })),
}));
```

## 5. Комментарии в тестах

Каждый тест-файл начинается с пояснения, что проверяется.
Каждый `it(...)` описывает проверяемое поведение на русском.

```typescript
// Тесты storage-слоя фотографий.
// Проверяем сохранение в sandbox и удаление файла.
```

## 6. Чего НЕ делать

- Не оставлять закомментированный «мёртвый» код.
- Не писать комментарии, дублирующие код дословно
  (`// увеличиваем i на 1` для `i++` — бессмысленно).
- Не смешивать языки: пояснения — на русском, а не «Russian + English винегрет».
- Не оставлять TODO без пояснения — если TODO, то с описанием, что и почему.

## 7. Мини-чеклист документирования файла

- [ ] Есть шапка файла (назначение + функции + слой).
- [ ] Каждый логический блок имеет краткое пояснение.
- [ ] Нетривиальные функции имеют JSDoc на русском.
- [ ] Нет мёртвого кода и бессмысленных комментариев.
- [ ] Тесты прокомментированы (что проверяют).
