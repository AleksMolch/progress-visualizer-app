# Дополнение к заданию: уточнение Liquid Glass по эталонным скриншотам 5 и 6

Назначение: этот файл дополняет `DESIGN_REFINEMENT_PLATFORM_THEMES_TASK.md` и уточняет, каким именно должен быть стиль Liquid Glass по двум последним присланным референсам.

---

## 1. Главный вывод по референсам

Цель Liquid Glass — не просто размытый широкий tabbar внизу экрана. Цель — **компактная плавающая стеклянная капсула**, расположенная поверх контента, с внутренним активным сегментом-пилюлей.

Текущий вариант приложения, судя по скриншоту, слишком широкий и похож на обычную полупрозрачную нижнюю панель. Его нужно приблизить к референсу:

- меньше ширина;
- больше округлость;
- меньше высота;
- сильнее ощущение стеклянного материала;
- активный таб как отдельная внутренняя плашка;
- контент должен просматриваться под капсулой;
- края должны быть мягкими, с бликом и тонкой границей.

---

## 2. Визуальная спецификация Liquid Glass tabbar

### 2.1. Размер и позиционирование

Рекомендуемые ориентиры для iPhone-size экранов:

- ширина tabbar: примерно `54–68%` ширины экрана, а не full-width;
- maxWidth: `360`;
- minWidth: достаточно для 3 табов без обрезки текста;
- высота: `64–76`;
- позиция: bottom safe area + `10–18`;
- alignSelf: `center`;
- borderRadius: `999`;
- overflow: visible, если тень/свечение выходят за контейнер;
- сама стеклянная капсула должна иметь `overflow: hidden` для внутреннего blur/материала.

Если 3 таба не помещаются красиво с текстом, разрешено:

1. показывать иконку + короткий текст только у активной вкладки;
2. у неактивных показывать только иконку;
3. либо использовать очень короткие подписи: `Проекты`, `Камера`, `Опции`.

Не делать таббар на всю ширину экрана в стиле текущего скриншота.

### 2.2. Материал капсулы

На поддерживаемой iOS:

- использовать native glass / `expo-glass-effect`, если установлен и доступен;
- перед использованием проверять доступность API и reduce transparency;
- не анимировать opacity родителя `GlassView`, если документация предупреждает о проблемах.

Fallback:

- `expo-blur` или обычная полупрозрачная поверхность;
- background light: `rgba(255, 255, 255, 0.45–0.65)`;
- background dark: `rgba(20, 20, 22, 0.45–0.65)`;
- border: `rgba(255,255,255,0.35)` на светлом фоне и `rgba(255,255,255,0.16)` на тёмном;
- shadow: мягкая, не тяжёлая.

Важно: на Android не обещать настоящий iOS Liquid Glass. Android может получить fallback-стиль, но default на Android — Material Design.

### 2.3. Активный сегмент

Внутри капсулы активная вкладка должна выглядеть как отдельная мягкая пилюля:

- borderRadius: `999`;
- paddingHorizontal: `12–18`;
- height: `46–54`;
- background:
  - light glass: `rgba(255,255,255,0.55–0.75)`;
  - dark glass: `rgba(60,60,64,0.45–0.65)`;
- border: тонкий highlight;
- иконка и текст активного таба — акцентным синим;
- неактивные иконки — белые/серые в зависимости от контраста фона;
- активный сегмент желательно анимировать Reanimated layout transition, но не ценой конфликта с Expo Router.

Если активный сегмент не получается плавно двигать между табами без переписывания навигации, допустимо анимировать только opacity/scale выбранной вкладки.

## 3. Поведение поверх контента

На референсах tabbar расположен поверх изображения/карточки. В приложении нужно:

- дать спискам нижний `contentContainerStyle.paddingBottom`, чтобы последний элемент не прятался;
- на камере поднять shutter/controls выше tabbar;
- на экранах project/gallery не закрывать кнопки удаления/экспорта;
- tabbar не должен перехватывать жесты вне своей капсулы;
- внешняя область вокруг капсулы должна пропускать касания к экрану.

Для gesture layer камеры важно: зона tabbar и её hitSlop не считается «свободным фоном» для жеста включения призрака 90%.

---

## 4. Чего НЕ делать

- Не делать wide pill почти на всю ширину, как в текущем скриншоте.
- Не делать непрозрачную сиреневую/серую плашку без настоящего blur/fallback-логики.
- Не использовать тяжёлые постоянные анимированные blur/gradient фоны.
- Не размывать пользовательские фото как часть карточек.
- Не менять тип навигатора на native tabs только ради визуала, если это ломает текущую структуру.
- Не скрывать подписи всех табов без альтернативы: пользователю должно быть понятно, где Проекты, Камера, Настройки.

---

## 5. Acceptance criteria для Liquid Glass

Liquid Glass считается улучшенным, если:

- [ ] tabbar компактный, плавающий, центрированный, не full-width;
- [ ] активный таб выглядит как отдельная внутренняя пилюля;
- [ ] материал визуально отличается от обычной прозрачной панели;
- [ ] на iOS используется native glass или корректный fallback;
- [ ] на Android Liquid Glass не является default и не выдаётся за настоящий iOS-эффект;
- [ ] контент виден под панелью, но текст/иконки остаются читаемыми;
- [ ] последний элемент списка не перекрывается;
- [ ] camera controls и shutter не конфликтуют с панелью;
- [ ] жест призрака 90% не срабатывает при тапе по tabbar;
- [ ] reduce transparency даёт непрозрачный, но красивый fallback.

---

## 6. Инструкция для ИИ-разработчика

Перед реализацией Liquid Glass открой последние референсы пользователя. Цель — компактная стеклянная капсула из примеров, а не текущая широкая нижняя панель. Сначала реализуй визуальное поведение через существующий Expo Router JS Tabs и кастомизацию tabbar. Не меняй тип навигации и не добавляй `react-native-bottom-tabs`, пока не докажешь, что текущий подход не позволяет получить приемлемый результат.

Если потребуется новый компонент, сделай его тонким и локальным:

- `src/features/navigation/components/liquid-glass-tab-bar.tsx`

Он должен использовать текущие navigation state/descriptors, сохранять accessibility, tabPress/tabLongPress и не плодить историю переходов.
